# #Javascript 기본 지식

## DOM

> **DOM = 문서 객체 모델(Document Object Model)** : Tree 구조를 갖게 됨

- `document` : DOM 트리 최상위 노드

  ```javascript
  document.getRootNode(); // 결과 : #document

  document.childNodes[1].childNodes[2].childNodes[1].textContent = "제목입니다";
  let domObject = document.querySelector("h1");
  domObject.textContent = "변경합니다~!";
  ```

📌 [DOM 소개 - 프로퍼티 확인] (https://developer.mozilla.org/ko/docs/Web/API/Document_Object_Model/Introduction)

## BOM

> **BOM = 브라우저 객체 모델(Browser Object Model)**

- `window` : 모든 객체가 소속된 객체이며, 브라우저 창을 의미
- `document` : 현재 문서에 대한 정보를 갖고 있는 객체
- `history` : 현재의 브라우저가 접근했던 URL history를 제어할 수 있음
- `location` : 문서의 주소와 관련된 객체, window 객체의 프로퍼티인 동시에 document의 프로퍼티(윈도우의 문서 URL을 변경할 수 있고, 문서의 위치와 관련해서 다양한 정보를 얻을 수 있음)
- `screen` : 사용자의 디스플레이 화면에 대한 다양한 정보를 갖고 있는 객체
- `navigator` : 실행중인 애플리케이션(브라우저)에 대한 정보를 알 수 있음, 크로스 브라우징 이슈 해결 시 사용할 수 있음(예: `Chrome -> addEventListener, IE -> attachEvent`)
  - `navigator.geolocation.getCurrentPosition()` : 현재 애플리케이션에 대한 위치 정보
  - `navigator.appName` : 앱 이름 반환
  - `navigator.appVersion` : 앱에 대한 버전 정보 반환
  - `navigator.userAgent` : 서버에 요청할 때 앱에 대한 정보

```javascript
window.open("https://google.com");
window.close();
alert("경고창"); // window 생략 가능

document.querySelector("#custom-id").textContent = "원하는 텍스트";

history.back();
history.forward();

location.host;
location.href = "https://google.com";

console.dir(screen); // 현재 디스플레이 사이즈 확인 가능

navigator.geolocation.getCurrentPosition(function (pos) {
  var crd = pos.coords;

  console.log("Your current position is: ");
  console.log(`Latitude : ${crd.latitude}`);
  console.log(`Longitude : ${crd.longitude}`);
  console.log(`More of less ${crd.accuracy} meters.`);
});
```

📌 [navigator.geolocation.getCurrentPosition() 사용법] (https://developer.mozilla.org/ko/docs/Web/API/Geolocation/getCurrentPosition)

## load, defer, async

### 1. load 이벤트 리스너 등록

- `window.onload` : HTML 파싱 DOM 생성 그리고 외부 콘텐츠가 로드된 후 발생하는 이벤트
  ```javascript
  window.onload = function () {
    alert("onload");
  };
  ```
- `DOMContentLoaded` : HTML 파싱 DOM 생성 후 발생하는 이벤트
  ```javascript
  document.addEventListener("DOMContentLoaded", function () {
    alert("DOMContentLoaded");
  });
  ```

### 2. HTML5 script 로드 해결방법

> **defer, async** 속성을 통해 비동기 script 로드가 가능해져 로드 문제 근본적으로 해결

- `defer` 속성 : HTML 파싱과 함께, 비동기로 javascript 파일을 불러옴
  - **HTML 파싱이 완료된 후** javascript 코드 실행
  ```html
  <script src="script.js" defer></script>
  ```
- `async` 속성 : HTML 파싱과 함께, 비동기로 javascript 파일을 불러옴
  - **HTML 파싱이 완료되지 않았더라도, 먼저 로딩되는 javascript 파일부터** 실행 시작
  - javascript 파일 실행할 때는 HTML 파싱이 중단됨
  ```html
  <script src="script.js" async></script>
  ```

## this

> 대부분의 경우 **this**의 값은 **함수를 호출한 방법에 의해 결정**

- `this`는 호출한 놈
- 호출한 놈이 없을 경우에는 기본값으로 `window` 객체

```javascript
function printThis() {
  console.log(this); // default this => window
}
printThis();

let person1 = {
  name: "홍길동1",
  printThis: printThis,
};
person1.printThis();

let person2 = {
  name: "홍길동2",
  printThis: printThis,
};
person2.printThis();

let person3 = {
  name: "홍길동3",
  printThis: printThis,
};
person3.printThis();
```

- ❗️ 예외
  - 전역스코프에서 `this`는 window 객체
  - 화살표 함수에서 `this`가 조금 달라짐
  - Strict Mode에서는 `this`가 조금 달라짐

### 1. Arrow Function this

- 화살표 함수가 나오기 전까지는 함수가 어떻게 호출되는지에 따라 자신의 `this`값을 정의
- 하지만 화살표 함수는 자신을 포함하고 있는 외부 Scope에서 `this`를 계승받음
- 화살표 함수에서 `this`는 자신을 감싼 정적 범위

```javascript
let person = {
  name: "짐코딩",
  age: 20,
  hello: function () {
    setTimeout(() => {
      console.log(this); // person
    }, 1000);
  },
};
person.hello();
```

### 2. Strict Mode this

- 엄격 모드에서는 호출한 놈이 없을 경우 기본값을 `window`로 하지 않고 `undefined`로 함

```javascript
"use strict";

function printThis() {
  console.log(this); // 'use strict' 사용 시 => undefined
}
printThis();
```

# #IT 용어 이해

## API

> **API(Application Programming Interface)** : 응용 프로그램에서 사용할 수 있도록 운영체제나 프로그래밍 언어가 제공하는 기능을 제어할 수 있게 만든 인터페이스

- `Interface` : 상호간에 소통을 위해 만들어진 접점
- `UI(User Interface)` : 사용자가 소통하기 위한 접점
- `API` : 애플리케이션에서 데이터를 읽거나 쓰기 위해 사용하는 인터페이스
- `Private API` : 공개되지 않는 API
- `Public API(Open API)` : 공개되어 사용가능한 API
- `HTTP API` : 프로토콜 = 소통방법 = 통신방법 = 통신규약

## 동기와 비동기

- `비동기(Asynchronous)` : 답변을 기다리지 않는 것
  - 자원을 효율적으로 사용할 수 있으나 결과 확인이 어려움
  - 결과 확인을 위해 업무 프로세스가 추가되므로 업무가 복잡해질 수 있음
  - `Non-blocking` : 기다리지 않는 상태
- `동기(Synchronous)`: 답변을 기다리는 것
  - 업무가 단순하며, 자원을 비효율적으로 사용함
  - `Blocking` : 기다리는 상태
  - 지난 과정의 결과가 다음 과정에 영향을 끼치는 경우 동기 작업 방식이 더 효율적임

```javascript
// 동기식으로 실행해야 하는 경우
function 업무_프로세스() {
  A계좌로_인출하기();

  B계좌로_송금하기();
}

function A계좌로_인출하기() {
  console.log("A계좌 인출하기");
}

function B계좌로_송금하기() {
  console.log("B계좌 송금하기");
}
```

## 프론트엔드&백엔드

- **프론트엔드(클라이언트)** : 웹사이트에서 사용자들이 사용하는 화면과 같은 앞단
- **백엔드(서버)** : 눈에 보이지 않는 영역으로 API와 같은 뒷단
