# #Vue.js 인스턴스

## [인스턴스]

> 클래스의 실체화된 객체를 의미, 특정 클래스의 상태를 나타냄

- **클래스**가 객체를 생성하기 위한 템플릿이라면, **인스턴스**는 해당 클래스의 실제 객체

```javascript
import "./assets/main.css";

import { createApp } from "vue"; // 1
import App from "./App.vue";

createApp(App).mount("#app"); // 2
```

1. `createApp()` 함수는 뷰 패키지에 정의된 Vue 클래스의 인스턴스를 생성하는 역할을 하는 함수
2. `createApp()` 함수로 Vue 인스턴스 생성하고, 생성한 인스턴스를 `mount()` 함수로 HTML DOM과 연결

## [인스턴스의 구성 요소]

```javascript
// main.js
import { createApp, h } from "vue";

createApp({
  data() {
    return {
      message: "Hello, Vue!",
    };
  },
  methods: {
    reverse() {
      this.message = this.message.split("").reverse().join("");
    },
  },
  render() {
    // data와 methods에 정의한 속성 사용
    return h("div", [
      h("p", this.message),
      h("button", { onClick: this.reverse }, "Reverse"),
    ]);
  },
}).mount("#app");
```

- **인스턴스의 구성 요소** : `data`, `methods`, `render`와 같은 속성들

# #Vue 3 핵심 문법

## [Single File Component]

> **Single File Component(SFC)** : 하나의 파일에 인스턴스 구성 요소와 관련한 모든 코드가 포함되는 형식

```html
<!-- App.vue -->
<script setup>
  export default {};
</script>
<template></template>
<style scoped></style>
```

### 1. \<script> 태그 영역

- 템플릿에서 사용한 반응성을 가지는 변수 등을 조작 가능
- 자바스크립트나 타입스크립트 등을 이용해 스크립트 코드 작성
- `setup` 속성을 같이 이용하면 `LOC`의 양을 획기적으로 줄일 수 있음
- **옵션스 API** : 뷰에서 객체를 작성할 때 지켜야 하는 문법 규칙

### 2. \<template> 태그 영역

- 컴포넌트가 렌더링되어야 하는 `HTML` 코드 부분
- 선언적 렌더링 혹은 템플릿 문법을 이용하여 반응형 컴포넌트 생성 가능
- `<script>` 태그 영역에서 작성한 여러 속성으로 정의한 값들과 연동할 수 있음

### 3. \<style> 태그 영역

- 컴포넌트 혹은 전체 프로젝트에서 사용할 `CSS` 코드 삽입
- `scoped` 속성 이용 시 `CSS`가 컴포넌트에만 적용

## [컴포지션 함수 setup]

> **setup** 함수를 구성하는 내용은 자바스크립트를 작성하듯이 스크립트로 작성

```javascript
setup() {
  const data = 1
  return { data }
}
```

- 기존 `methods` 옵션으로 제공하던 함수의 경우 변수로 할당하여 반환

  ```javascript
  const foo = () => {
    data = 2;
  };
  return { foo };
  ```

## [Vue 컴포넌트의 생명주기]

> **생명주기** : 컴포넌트를 생성하여 DOM 노드 트리에 마운트하고, 불필요한 엘리먼트를 제거하는 일련의 과정

> **생명주기 훅** : Vue는 각 생명주기를 후킹할 수 있는 방법을 제공

```javascript
updated() {
  // Update Action
}

// 컴포지션 API
setup() {
  onUpdated(() => {
    // Update Action
  })
}
```

- `beforeCreate` : 컴포넌트를 생성하기 전에 호출
  - 컴포지션 API의 setup 함수 그 자체가 대체
  - 생성한 data는 물론, 해당 data를 관찰할 수 있는 watch와 같은 함수들이 동작하지 않음
- `created` : 컴포넌트가 생성되면 호출
  - 컴포지션 API의 setup 함수가 beforeCreate와 함께 created도 대체
  - 컴포넌트의 옵션에 접근 가능하므로 data 옵션에 선언한 데이터들을 초기화할 때 많이 사용
- `beforeMount(onBeforeMount)` : Vue의 가상 노드가 render 함수를 호출하기 직전에 호출
  - 실제 DOM을 구성하기 직전에 호출
  - 이 사이클이 지나고나면 Vue는 Virtual DOM에 가상으로 렌더링할 DOM을 미리 구성
  - onRenderTracked라는 생명주기 훅을 통해 관찰
- `mounted(onMounted)` : 실제로 컴포넌트의 구성요소들이 DOM 엘리먼트로 마운트된 후 호출
  - 해당 변수를 통해 엘리먼트에 접근 가능
  - Virtual DOM이 실제 DOM에 반영이 되었음을 의미
  - onRenderTriggered라는 생명주기 훅이 이후 호출됨
- `beforeUpdate(onBeforeUpdated)` : 데이터가 변경되었지만 아직 DOM에 반영되지 않았을 때 호출
  - Virtual DOM이 수정되고 이 수정사항이 DOM에 반영되기 직전에 호출되는 것
  - 실제 엘리먼트를 참조하는 변수로부터 아무것도 얻을 수 없음
- `updated(onUpdated)` : 데이터가 변경되어 DOM이 변경완료된 시점에 호출
  - DOM이 업데이트되었음
  - 해당 DOM에 참조된 변수를 이용해 다양한 역할 수행
  - 현재 컴포넌트만 수정이 되었음을 보장
  - 자식 컴포넌트까지 모두 수정된 것을 기다리기 위해서는 nextTick을 이용해 모든 자식의 업데이트가 완료되었음을 기다려야 함
    ```javascript
    updated() {
      this.$nextTick(function() {
        // 모든 자식이 업데이트 되었다.
      })
    }
    ```
- `beforeUnmount(onBeforeUnmount)` : 컴포넌트가 탈착되기 직전에 호출
  - 아직 모든 기능을 사용할 수 있는 상태
  - 명시적으로 컴포넌트가 Unmount되기 전에 해줘야 할 것들을 작성
- `unmounted(onUnmounted)` : 컴포넌트가 탈착되고 나서 호출
  - 모든 디렉티브와 이벤트가 사용이 불가능해짐
- `activated(onActivated)`
  - keep-alive 태그는 컴포넌트가 다시 렌더링되는 것을 방지하고 상태를 유지하기 위해 쓰임
  - v-is 디렉티브가 컴포넌트를 변경할 때 기존 컴포넌트의 상태가 사라지지 않게 하기 위해 사용
  - 컴포넌트의 상태가 보존되기 시작하면 onActivated 생명주기 훅 함수 호출
    ```html
    <keep-alive>
      <component v-is="currentComponent" />
    </keep-alive>
    ```
- `deactivated(onDeactivated)` : keep-alive로 상태가 유지되던 컴포넌트가 효력을 상실하면 호출
- `renderTracked(onRenderTracked)` : Virtual DOM이 변경될 때마다 관찰을 목적으로 해당 생명주기 훅이 호출
  - DebuggerEvent 객체를 살펴보면 어떠한 이유로 Virtual DOM이 변경이 되는지 알 수 있음
    ```javascript
    renderTracked(e) {
      console.log(e.target)
    }
    ```
- `renderTriggered(onRenderTriggered)` : Virtual DOM이 DOM으로 반영이 되어야 할 때 호출
  - 실제 DOM이 변경되기 직전에 호출
  - DebuggerEvent 객체를 살펴보면 어떠한 이유로 렌더링이 호출되었는지 파악 가능
- `errorCaptured(onErrorCaptured)` : 자손 컴포넌트에 에러가 발생하면 어느 컴포넌트에서 어떤 에러가 발생했는지 알려줌
  - 개발 중 에러를 캡쳐하기 위해 사용

## [선언적 렌더링]

> **선언적 렌더링** : 변수를 선언하고 값을 넣으면 자동으로 DOM에 업데이트

> **수염표기법(Mustache syntax)** : 템플릿에서 변수의 값을 나타내기 위해서 해당 변수를 두 개의 중괄호로 감싸서 표기

```html
<!-- Declarative-Rendering/App.vue -->
<script>
  export default {
    // Composition API
    setup() {
      const date = Date().toString();
      return {
        date,
      };
    },

    // Options API
    data() {
      return {
        date2: Date().toString(),
      };
    },
  };
</script>

<template>
  <div id="date">{% raw %}{{ date }}{% endraw %}</div>
  <div id="date2">{% raw %}{{ date2 }}{% endraw %}</div>
  <!-- 결과 : Sat Nov 08 2025 00:11:54 GMT+0900 (한국 표준시)
            Sat Nov 08 2025 00:11:54 GMT+0900 (한국 표준시) -->
</template>
```

### 1. v-html 디렉티브를 이용한 HTML 표현

- 문자열이 `HTML` 마크업 언어로 표현되도록 함

```html
<!-- v-html/App.vue -->
<script>
  export default {
    setup() {
      const text = "<h1>HTML TEXT</h1>";
      return {
        text,
      };
    },
  };
</script>

<template>
  <div v-html="text"></div>
  <!-- 결과 : HTML TEXT -->
</template>
```

### 2. v-pre 디렉티브를 이용한 컴파일 무시

- 해당 엘리먼트를 포함한 모든 자식 엘리먼트들의 값을 컴파일하지 않음

```html
<!-- v-pre/App.vue -->
<script>
  export default {
    setup() {
      const text = "HTML TEXT";
      return {
        text,
      };
    },
  };
</script>

<template>
  <div>{% raw %}{{ text }}{% endraw %}</div>
  <!-- 결과 : HTML TEXT -->
  <div v-pre>{% raw %}{{ text }}{% endraw %}</div>
  <!-- 결과 : {% raw %}{{ text }}{% endraw %} -->
</template>
```

## [데이터 결합을 통한 사용자 입력 처리]

### 1. v-bind 디렉티브

`v-bind:HTML 속성 = "변수명"`

`:HTML속성 = "변수명" -> 콜론으로 대체 가능`

- 단방향 결합 지원 : 변수의 값이 템플릿으로만 결합되어 템플릿의 HTML 태그가 변경한 값이 변수에 돌아오지 않음

### 2. v-model 디렉티브

- 양방향 결합 지원 : 변수의 변경이 템플릿의 DOM에 영향을 미침, 템플릿에서의 변경이 변수의 값을 변경시킴

```html
<!-- responsive-variable/App.vue -->
<script>
  import { ref } from "vue";

  export default {
    // Composition API
    setup() {
      const abbr = ref("DOPT");
      const normal = ref("Dong Project Team");
      return {
        abbr,
        normal,
      };
    },
  };
</script>

<template>
  <p>줄임말과 원래말을 입력하세요.</p>
  <!-- 변경 불가능 -->
  <input type="text" v-bind:value="abbr" />
  <!-- 변경 가능 -->
  <input type="text" v-model="normal" />
  <hr />
  <abbr v-bind:title="normal">{% raw %}{{ abbr }}{% endraw %}</abbr>
</template>
```

#### 💡 ref 문법

- `<script setup>`을 이용하면 components 옵션도 필요 없고, `setup` 함수를 만들 필요도 없으며, 명시적으로 변수를 반환해야 할 일도 없음
- ref를 다음과 같이 이용하면 뒤에 `value` 속성을 이용하지 않아도 됨
  ```html
  <script setup>
    ref: title = 'old'
    const change() => { title = 'new title' }
  </script>
  ```

- 변수의 값을 변경할 수 있는 수식어

## [이벤트 리스너를 이용한 사용자 입력 처리]

### 1. v-on 디렉티브

`v-on:click = "스크립트 코드, 혹은 함수 호출"`

`@click = "스크립트 코드, 혹은 함수 호출"`

- HTML 태그가 발생시키는 이벤트를 캡쳐하여 지정된 스크립트를 수행하거나 함수를 호출
- 사용자가 만든 컴포넌트에서 발생된 이벤트를 캡쳐할 때도 사용하는 매우 유용한 디렉티브

```html
<script>
  import { ref } from "vue";

  export default {
    data() {
      return {
        counter2: 0,
      };
    },
    setup() {
      // ref 함수로 선언된 변수는 프록시 객체로 변환됨
      let counter = ref(0);

      const onClick = (evt) => {
        if (evt) {
          evt.preventDefault();
          counter.value++;
        }
      };
      return {
        counter,
        onClick,
      };
    },
    methods: {
      // Options API를 통해 구현한 함수
      onClick2: function (evt) {
        if (evt) {
          evt.preventDefault();
        }
        // this.counter2++;
      },
    },
  };
</script>

<template>
  <p>{{ counter + counter2 }}</p>
  <!-- counter 변수 직접 참조 -->
  <button @click="counter++">클릭하면 숫자가 올라갑니다.</button>
  <!-- onClick 함수 호출 -->
  <!-- onClick2로 변경해도 같은 결과가 나옴 -->
  <button @click="onClick2">클릭하면 숫자가 올라갑니다.</button>
</template>
```

### 2. 이벤트 수식어

-
