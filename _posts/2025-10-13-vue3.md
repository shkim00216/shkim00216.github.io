# #컴포넌트란

## [컴포넌트 기반 아키텍처]

> **컴포넌트** : 통상적으로 특정 기능이나 작업을 독립적으로 수행하기 위한, 논리적으로 구분된 코드 단위

> **컴포넌트 기반 아키텍처** : 한 웹 애플리케이션을 여러 컴포넌트로 구분해, 페이지 단위가 아니라 컴포넌트 단위로 설계하는 방식 의미

### 컴포넌트 기반 아키텍처 설계 방식의 장점

1. **재사용성(reusability)** : 컴포넌트는 특정 기능이나 작업을 독립적으로 수행하는 단위이므로 같은 기능이나 작업이 필요한 곳에서 재사용할 수 있음
2. **독립성(independence)** : 컴포넌트는 독립적으로 작동할 수 있어야 함, 다른 컴포넌트에 영향을 주지 않고 특정 컴포넌트만 수정하거나 교체할 수 있음을 의미
3. **모듈성(modularity)** : 컴포넌트 기반 아키텍처는 웹 애플리케이션을 개별 단위로 구분하기 때문에 복잡성이 줄어듬
4. **확장성(extensible)** : 컴포넌트에서 구성 요소를 추가하거나 수정해 새로운 동작이나 기능을 제공할 수 있음
5. **캡슐화(encapsulation)** : 컴포넌트는 내부의 복잡성을 숨기고, 단순하게 기능만 사용할 수 있는 인터페이스를 제공하기도 함, 개발자는 컴포넌트의 내부 로직이나 상태 등을 알지 못해도 컴포넌트를 사용해 화면을 구성할 수 있음

## [뷰에서 컴포넌트의 개념]

- 뷰에서는 웹 애플리케이션을 만들기 위해 여러 컴포넌트를 **트리(tree) 구조**로 연결해 구성

# #컴포넌트 정의하기

## [싱글 파일 컴포넌트]

```html
<script></script>
<template></template>
<style></style>
```

- **`<script>` 태그 영역(선택)** : 컴포넌트의 로직 부분 담당, 자바스크립트로 코드 작성, 뷰에서 약속된 문법 형식 준수
- **`<template>` 태그 영역(필수)** : 컴포넌트의 렌더링 부분을 담당, HTML로 코드 작성, 뷰에서 자체적으로 제공하는 템플릿 문법을 함께 사용, 웹 브라우저에 표시
- **`<style>` 태그 영역(선택)** : 컴포넌트의 스타일 부분을 담당, CSS로 코드 작성, 설정에 따라 SCSS/LESS/SASS와 같은 CSS 전처리기 언어 사용 가능

### ❗️ 태그 작성 순서

- 뷰에서는 공식적으로 `<script> -> <template> -> <style>` 태그 순으로 작성하기를 권장

## [컴포넌트 생성하기]

- 컴포넌트 생성 : `src/components` 폴더에 만들도록 권장

### 💡 파스칼 케이스 권장

- 각 단어의 첫 글자를 대문자로 시작하게 작성
- 예) `PaymentList, UserInfo, MyProfile`

## [컴포넌트 등록하기]

### 1. 전역 등록

> **전역(global) 등록** : 컴포넌트를 뷰 애플리케이션의 모든 곳에서 사용할 수 있게 함

- `src > main.js` 파일에 등록
- `import`로 등록하며, **컴포넌트 인스턴스** 또는 **컴포넌트 객체**라고 함
- 애플리케이션 인스턴스 필요 => `component()` 함수 사용
  - 첫 번째 매개변수 : 전역으로 사용할 컴포넌트의 이름
  - 두 번째 매개변수 : 전역으로 등록할 컴포넌트 객체 지정

```javascript
// main.js
import { createApp } from "vue";
import App from "./App.vue";

// 전역 등록
// 컴포넌트 인스턴스 or 컴포넌트 객체
import FirstChild from "./components/FirstChild.vue";

const app = createApp(App);

// 애플리케이션 인스턴스
app.component("FirstChild", FirstChild);
app.mount("#app");
```

```html
<!-- App.vue/global-import -->
<template>
  <FirstChild></FirstChild>
</template>
```

### 2. 지역 등록

> **지역(local) 등록** : 컴포넌트를 등록한 곳에서만 사용할 수 있게 함

1. 지역 등록할 컴포넌트 불러옴
2. 옵션스 API의 `components` 속성을 사용해 컴포넌트를 할당
3. `components` 속성의 값은 `import` 키워드 다음에 적힌 식별자 그대로 사용

```html
<!-- App.vue/local-import -->
<script>
  // 지역 등록
  import FirstChild from "./components/FirstChild.vue";

  export default {
    components: {
      FirstChild,
    },
  };
</script>

<template>
  <FirstChild></FirstChild>
</template>
```

## [컴포넌트 스타일의 범위]

- **scoped 속성** : 뷰는 컴포넌트에 적용한 스타일이 해당 컴포넌트에만 적용되도록 함

```html
<!-- App.vue/style-scoped -->
<!-- APP 컴포넌트에만 영향을 줌 -->
<style scoped>
  h1,
  p {
    color: orange !important;
  }
</style>
```

# #컴포넌트 생명주기 이해하기

- **생명주기(lifecycle)** : 컴포넌트가 생성되고 파괴되기까지의 여러 단계 의미
- **마운트(mounted)** : 컴포넌트가 생성되고 생명주기의 여러 단계를 거치면서 마운트 상태가 되면 컴포넌트가 웹 브라우저에 보이게 됨
- **리렌더링** : 컴포넌트의 코드가 변경되어 화면이 갱신되면 컴포넌트는 변경된 데이터를 기반으로 화면을 다시 그림
- **패치** : 새롭게 그려진 가상 DOM을 실제 DOM과 비교해 변경된 부분만 실제 DOM에 갱신하는 과정
- **마운트 해제(unmounted)** : 한 번 마운트된 DOM에서 제거될 때까지 유지되며 DOM에서 제거되기 직전에 마운트 해제 상태가 되고 나서야 비로소 컴포넌트가 DOM에서 제거됨

## [라이프사이클 훅]

> **훅(hook)** : 특정 기능과 역할을 하는 함수

> **라이프사이클 훅(lifecycle hook)** : 컴포넌트에서 호출되는 훅

### 라이프사이클 훅의 호출 시점

| 라이프사이클 훅   | 호출 시점                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| `beforeCreate()`  | 뷰 애플리케이션 인스턴스가 초기화되고 데이터 및 이벤트가 설정되기 전에 호출                              |
| `created()`       | 뷰 애플리케이션 인스턴스가 생성된 직후에 호출, 데이터와 이벤트가 설정되어 있지만, DOM에는 접근할 수 없음 |
| `beforeMount()`   | 뷰 애플리케이션 인스턴스가 마운트되기 전에 호출, DOM에 접근할 수 있지만 마운트되기 전                    |
| `mounted()`       | 뷰 애플리케이션 인스턴스가 DOM에 마운트된 후에 호출, 인스턴스는 마운트된 상태이며 DOM에 접근할 수 있음   |
| `beforeUpdate()`  | 데이터가 변경되어 DOM이 갱신되기 전에 호출                                                               |
| `updated()`       | 데이터가 변경되어 DOM이 갱신된 후에 호출                                                                 |
| `beforeDestroy()` | 뷰 애플리케이션 인스턴스가 웹 브라우저에서 제거되기 전에 호출                                            |
| `destroyed()`     | 뷰 애플리케이션 인스턴스가 웹 브라우저에게 제거된 후에 호출                                              |

```html
<!-- FirstChild.vue/lifestyle -->
<script>
  export default {
    beforeUnmount() {
      console.log("beforeUnmount");
    },
    unmounted() {
      console.log("unmounted");
    },
  };
</script>

<template>
  <h1>First Child</h1>
</template>
```

```html
<!-- App.vue/lifestyle -->
<script>
  import FirstChild from "./components/FirstChild.vue";

  export default {
    data() {
      return {
        visible: true,
      };
    },
    beforeCreate() {
      console.log("beforeCreate");
    },
    components: {
      FirstChild,
    },
    created() {
      setTimeout(() => {
        this.visible = false;
      }, 3000);
    },
    beforeMount() {
      console.log("beforeMount");
    },
    mounted() {
      console.log("mounted");
    },
    beforeUpdate() {
      console.log("beforeUpdate");
    },
    updated() {
      console.log("updated");
    },
  };
</script>

<template>
  <FirstChild v-if="visible"></FirstChild>
</template>

<!-- 결과 -->
<!-- beforeCreate
beforeMount
mounted
beforeUpdate
beforeUnmount
unmounted
updated -->
```
