# #컴포넌트란

## [컴포넌트 기반 아키텍처]

> **컴포넌트** : 통상적으로 특정 기능이나 작업을 독립적으로 수행하기 위한, 논리적으로 구분된 코드 단위

> **컴포넌트 기반 아키텍처** : 한 웹 애플리케이션을 여러 컴포넌트로 구분해, 페이지 단위가 아니라 컴포넌트 단위로 설계하는 방식 의미

### 컴포넌트 기반 아키텍처 설계 방식의 장점

1. **재사용성(reusability)** : 컴포넌트는 특정 기능이나 작업을 독립적으로 수행하는 단위이므로 같은 기능이나 작업이 필요한 곳에서 재사용할 수 있음
2. **독립성(independence)** : 컴포넌트는 독립적으로 작동할 수 있어야 함, 다른 컴포넌트에 영향을 주지 않고 특정 컴포넌트만 수정하거나 교체할 수 있음을 의미
3. **모듈성(modularity)** : 컴포넌트 기반 아키텍처는 웹 애플리케이션을 개별 단위로 구분하기 때문에 복잡성이 줄어듬
4. **확장성(extensible)** : 컴포넌트에서 구성 요소를 추가하거나 수정해 새로운 동작이나 기능을 제공할 수 있음
5. **캡슐화(encapsulation)** : 컴포넌트는 내부의 복잡성을 숨기고, 단순하게 기능만 사용할 수 있는 인터페이스를 제공하기도 함, 개발자는 컴포넌트의 내부 로직이나 상태 등을 알지 못해도 컴포넌트를 사용해 화면을 구성할 수 있음

## [뷰에서 컴포넌트의 개념]

- 뷰에서는 웹 애플리케이션을 만들기 위해 여러 컴포넌트를 **트리(tree) 구조**로 연결해 구성

# #컴포넌트 정의하기

## [싱글 파일 컴포넌트]

```html
<script></script>
<template></template>
<style></style>
```

- **`<script>` 태그 영역(선택)** : 컴포넌트의 로직 부분 담당, 자바스크립트로 코드 작성, 뷰에서 약속된 문법 형식 준수
- **`<template>` 태그 영역(필수)** : 컴포넌트의 렌더링 부분을 담당, HTML로 코드 작성, 뷰에서 자체적으로 제공하는 템플릿 문법을 함께 사용, 웹 브라우저에 표시
- **`<style>` 태그 영역(선택)** : 컴포넌트의 스타일 부분을 담당, CSS로 코드 작성, 설정에 따라 SCSS/LESS/SASS와 같은 CSS 전처리기 언어 사용 가능

### ❗️ 태그 작성 순서

- 뷰에서는 공식적으로 `<script> -> <template> -> <style>` 태그 순으로 작성하기를 권장

## [컴포넌트 생성하기]

- 컴포넌트 생성 : `src/components` 폴더에 만들도록 권장

### 💡 파스칼 케이스 권장

- 각 단어의 첫 글자를 대문자로 시작하게 작성
- 예) `PaymentList, UserInfo, MyProfile`

## [컴포넌트 등록하기]

### 1. 전역 등록

> **전역(global) 등록** : 컴포넌트를 뷰 애플리케이션의 모든 곳에서 사용할 수 있게 함

- `src > main.js` 파일에 등록
- `import`로 등록하며, **컴포넌트 인스턴스** 또는 **컴포넌트 객체**라고 함
- 애플리케이션 인스턴스 필요 => `component()` 함수 사용
  - 첫 번째 매개변수 : 전역으로 사용할 컴포넌트의 이름
  - 두 번째 매개변수 : 전역으로 등록할 컴포넌트 객체 지정

```javascript
// main.js
import { createApp } from "vue";
import App from "./App.vue";

// 전역 등록
// 컴포넌트 인스턴스 or 컴포넌트 객체
import FirstChild from "./components/FirstChild.vue";

const app = createApp(App);

// 애플리케이션 인스턴스
app.component("FirstChild", FirstChild);
app.mount("#app");
```

```html
<!-- App.vue/global-import -->
<template>
  <FirstChild></FirstChild>
</template>
```

### 2. 지역 등록

> **지역(local) 등록** : 컴포넌트를 등록한 곳에서만 사용할 수 있게 함

1. 지역 등록할 컴포넌트 불러옴
2. 옵션스 API의 `components` 속성을 사용해 컴포넌트를 할당
3. `components` 속성의 값은 `import` 키워드 다음에 적힌 식별자 그대로 사용

```html
<!-- App.vue/local-import -->
<script>
  // 지역 등록
  import FirstChild from "./components/FirstChild.vue";

  export default {
    components: {
      FirstChild,
    },
  };
</script>

<template>
  <FirstChild></FirstChild>
</template>
```

## [컴포넌트 스타일의 범위]

- **scoped 속성** : 뷰는 컴포넌트에 적용한 스타일이 해당 컴포넌트에만 적용되도록 함

```html
<!-- App.vue/style-scoped -->
<!-- APP 컴포넌트에만 영향을 줌 -->
<style scoped>
  h1,
  p {
    color: orange !important;
  }
</style>
```

# #컴포넌트 생명주기 이해하기

- **생명주기(lifecycle)** : 컴포넌트가 생성되고 파괴되기까지의 여러 단계 의미
- **마운트(mounted)** : 컴포넌트가 생성되고 생명주기의 여러 단계를 거치면서 마운트 상태가 되면 컴포넌트가 웹 브라우저에 보이게 됨
- **리렌더링** : 컴포넌트의 코드가 변경되어 화면이 갱신되면 컴포넌트는 변경된 데이터를 기반으로 화면을 다시 그림
- **패치** : 새롭게 그려진 가상 DOM을 실제 DOM과 비교해 변경된 부분만 실제 DOM에 갱신하는 과정
- **마운트 해제(unmounted)** : 한 번 마운트된 DOM에서 제거될 때까지 유지되며 DOM에서 제거되기 직전에 마운트 해제 상태가 되고 나서야 비로소 컴포넌트가 DOM에서 제거됨

## [라이프사이클 훅]

> **훅(hook)** : 특정 기능과 역할을 하는 함수

> **라이프사이클 훅(lifecycle hook)** : 컴포넌트에서 호출되는 훅

### 라이프사이클 훅의 호출 시점

| 라이프사이클 훅   | 호출 시점                                                                                                |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| `beforeCreate()`  | 뷰 애플리케이션 인스턴스가 초기화되고 데이터 및 이벤트가 설정되기 전에 호출                              |
| `created()`       | 뷰 애플리케이션 인스턴스가 생성된 직후에 호출, 데이터와 이벤트가 설정되어 있지만, DOM에는 접근할 수 없음 |
| `beforeMount()`   | 뷰 애플리케이션 인스턴스가 마운트되기 전에 호출, DOM에 접근할 수 있지만 마운트되기 전                    |
| `mounted()`       | 뷰 애플리케이션 인스턴스가 DOM에 마운트된 후에 호출, 인스턴스는 마운트된 상태이며 DOM에 접근할 수 있음   |
| `beforeUpdate()`  | 데이터가 변경되어 DOM이 갱신되기 전에 호출                                                               |
| `updated()`       | 데이터가 변경되어 DOM이 갱신된 후에 호출                                                                 |
| `beforeDestroy()` | 뷰 애플리케이션 인스턴스가 웹 브라우저에서 제거되기 전에 호출                                            |
| `destroyed()`     | 뷰 애플리케이션 인스턴스가 웹 브라우저에게 제거된 후에 호출                                              |

```html
<!-- FirstChild.vue/lifestyle -->
<script>
  export default {
    beforeUnmount() {
      console.log("beforeUnmount");
    },
    unmounted() {
      console.log("unmounted");
    },
  };
</script>

<template>
  <h1>First Child</h1>
</template>
```

```html
<!-- App.vue/lifestyle -->
<script>
  import FirstChild from "./components/FirstChild.vue";

  export default {
    data() {
      return {
        visible: true,
      };
    },
    beforeCreate() {
      console.log("beforeCreate");
    },
    components: {
      FirstChild,
    },
    created() {
      setTimeout(() => {
        this.visible = false;
      }, 3000);
    },
    beforeMount() {
      console.log("beforeMount");
    },
    mounted() {
      console.log("mounted");
    },
    beforeUpdate() {
      console.log("beforeUpdate");
    },
    updated() {
      console.log("updated");
    },
  };
</script>

<template>
  <FirstChild v-if="visible"></FirstChild>
</template>

<!-- 결과 -->
<!-- beforeCreate
beforeMount
mounted
beforeUpdate
beforeUnmount
unmounted
updated -->
```

⭐️ 생명주기의 어느 시점에서 어떤 라이프사이클 훅이 호출되는지 알아야 함

## [템플릿 ref]

> **ref 속성** : 문서 객체(DOM)을 참조할 때와 컴포넌트를 참조할 때 사용

### 1. 문서 객체 참조

- 일반적인 자바스크립트 문법에서는 HTML로 작성된 태그의 문서 객체(DOM)을 참조할 때 `document` 객체 사용
- 뷰에서도 `<template>` 태그에 사용된 HTML 태그의 문서 객체에 접근할 때 `document` 객체 사용 가능
- 하지만 뷰에서는 자체적인 반응형 시스템과의 통합을 위해 `ref` 속성을 사용한 참조를 더 권장함

  ```html
  <!-- App.vue/ref -->
  <script>
    export default {
      mounted() {
        const domEl = this.$refs.domEl;
        const text = domEl.innerText; // this.$refs.domEl.innerText와 같은 의미
        console.log(text);
      },
    };
  </script>

  <template>
    <h1 ref="domEl">h1 태그</h1>
  </template>
  ```

### 2. 컴포넌트 참조

```html
<!-- FirstChild.vue/ref2 -->
<script>
  export default {
    data() {
      return {
        num: 5,
      };
    },
    computed: {
      doubleNum() {
        return this.num * 2;
      },
    },
    methods: {
      increment() {
        this.num++;
      },
    },
  };
</script>

<template>
  <h1>{% raw %}{{ num }}{% endraw %}</h1>
</template>
```

- App 컴포넌트는 `$ref` 객체에 저장된 FirstChild 컴포넌트에 대한 참조 속성을 사용해 FirstChild 컴포넌트에 정의된 `data, computed, methods` 옵션 속성에 접근 가능

```html
<!-- App.vue/ref2 -->
<script>
  import FirstChild from "./components/FirstChild.vue";

  export default {
    components: {
      FirstChild,
    },
    mounted() {
      const childNum = this.$refs.child.num;
      const childDoubleNum = this.$refs.child.doubleNum;
      console.log(`메서드 호출 전: ${childNum}`); // 5
      console.log(`메서드 호출 전: ${childDoubleNum}`); // 10
      // DOM이 마운트되고 1초 뒤에 FirstChild 컴포넌트의 increment() 메서드 호출
      setTimeout(() => {
        this.$refs.child.increment();
        console.log(`메서드 호출 후: ${this.$refs.child.num}`); // 6
        console.log(`메서드 호출 후: ${this.$refs.child.doubleNum}`); // 12
      }, 1000);
    },
  };
</script>

<template>
  <FirstChild ref="child"></FirstChild>
</template>
```

- ❗️ 하지만 뷰에서는 이런 방식으로 자식 컴포넌트에 접근하거나 직접 조작하는 방식을 권장하지 않으니 정말로 어쩔 수 없을 때만 사용

# #컴포넌트에 속성과 이벤트 정의하기

## [컴포넌트의 사용자 정의 속성]

> **사용자 정의 속성** : 전역 등록하거나 지역 등록한 컴포넌트를 사용할 때 컴포넌트와 함께 속성 정의 가능, 해당 컴포넌트로 원하는 값을 전달할 때 사용

```html
<!-- UserProfile.vue/custom -->
<script>
  export default {
    props: ["name", "age"], // 사용자 정의 속성인 name, age의 값을 받음
  };
</script>

<template>
  <p>이름: {% raw %}{{ name }}{% endraw %}</p>
  <p>나이: {% raw %}{{ age }}{% endraw %}</p>
</template>
```

```html
<!-- App.vue/custom -->
<script>
  import UserProfile from "./components/UserProfile.vue";

  export default {
    components: {
      UserProfile,
    },
  };
</script>

<template>
  <UserProfile name="김철수" age="30"></UserProfile>
</template>
```

- `props` 옵션 속성으로 사용자 정의 속성의 값을 전달받으면 해당 컴포넌트의 내부에서 `data` 옵션 속성으로 정의한 값처럼 사용 가능

### props의 기본 자료형

- 사용자 정의 속성으로 컴포넌트에 전달하는 값은 기본적으로 문자열(string) 자료형

```html
<!-- App.vue/props -->
<script>
  import UserProfile from "./components/UserProfile.vue";

  export default {
    components: {
      UserProfile,
    },
    data() {
      return {
        name: "김철수",
        age: 30,
      };
    },
  };
</script>

<template>
  <!-- 원하는 자료형으로 변경 시 v-bind 바인딩 -->
  <UserProfile :name="name" :age="age"></UserProfile>
</template>
```

### 사용자 정의 속성의 기본값

1. 사용자 정의 속성만 지정하고 값을 할당하지 않음 -> `true`

   ```html
   <UserProfile isHuman /> <UserProfile :isHuman="true" />
   ```

2. `v-bind` 디렉티브를 사용하지 않으면 문자열 또는 숫자 값이 됨

   ```html
   <UserProfile isHuman="true" /> <UserProfile isHuman="30" />
   ```

### 사용자 정의 속성의 유효성 검사

- 속성 값의 자료형만 검사하는 방법

  ```javascript
  export default {
    props: {
      속성명: String | Number | Array | Object | Boolean | Function | Symbol,
    },
  };
  ```

  ```html
  <script>
    export default {
      props: {
        name: String, // name 속성의 값이 문자열인지 검사
        age: [String, Number], // age 속성의 값이 문자열이나 숫자인지 검사
      },
    };
  </script>

  <template>
    <p>이름: {% raw %}{{ name }}{% endraw %}</p>
    <p>나이: {% raw %}{{ age }}{% endraw %}</p>
  </template>
  ```

- 더 다양한 유효성 검사

  ```javascript
  export default {
    props: {
      속성명: {
        type: String | Number | Array | Object | Boolean | Function | Symbol,
        required: true,
        validator: function(value) {
          return true | false
        },
        default: function() {
          reutrn ""
        }
      }
    },
  };
  ```

  - `type` : 속성 값의 자료형 지정
  - `required` : 속성 값의 필수 여부 지정
  - `validator` : 속성 값의 유효성 검사 지정, 내부적으로 true 또는 false를 반환
  - `default` : 속성 값의 초깃값 지정, 속성 값이 전달되지 않으면 여기서 지정한 초깃값이 속성 값이 됨(`required`와 같이 사용 불가)

  ```html
  <!-- UserProfile.vue/valid2 -->
  <script>
    export default {
      props: {
        name: {
          type: String,
          required: true,
          validator: function (value) {
            return value.length > 1; // 이름이 최소 2글자 이상이어야 함
          },
        },
        age: {
          type: Number,
          default: function () {
            return 10;
          },
        },
      },
    };
  </script>

  <template>
    <p>이름: {% raw %}{{ name }}{% endraw %}</p>
    <p>나이: {% raw %}{{ age }}{% endraw %}</p>
  </template>
  ```

  ```html
  <!-- App.vue/valid2 -->
  <script>
    import UserProfile from "./components/UserProfile.vue";

    export default {
      components: {
        UserProfile,
      },
      data() {
        return {
          userName: "김철수",
        };
      },
    };
  </script>

  <template>
    <!-- name 속성은 필수 값, 글자수 2자 이상 -->
    <!-- age 속성은 옵션 값, 기본값 10 지정됨 -->
    <UserProfile :name="userName"></UserProfile>
  </template>
  ```

## [컴포넌트의 사용자 정의 이벤트]

```html
<template> <컴포넌트 @이벤트_타입="이벤트_핸들러" /> </template>
```

- 컴포넌트에서 사용하는 이벤트 타입은 하위 컴포넌트에서 부모 컴포넌트로 발신하는 이벤트를 수신하는 용도

```html
<!-- App.vue/custom-event -->
<script>
  import UserProfile from "./components/UserProfile.vue";

  export default {
    components: {
      UserProfile,
    },
    methods: {
      printHello() {
        alert("안녕하세요!");
      },
    },
  };
</script>

<template>
  <UserProfile @print-hello="printHello"></UserProfile>
</template>
```

### 이벤트 발신

> 모든 컴포넌트는 부모 컴포넌트로 이벤트 발신, **$emit()** 내장 메서드 사용

1. 인라인 핸들러 방식

   ```html
   <!-- UserProfile.vue/custom-event-inline -->
   <script>
     export default {};
   </script>

   <template>
     <button @click="$emit('print-hello')">클릭</button>
   </template>
   ```

2. 메서드 핸들러 방식

   ```html
   <!-- UserProfile.vue/cutom-event-methods -->
   <script>
     export default {
       methods: {
         parentEventCall() {
           this.$emit("print-hello");
         },
       },
     };
   </script>

   <template>
     <button @click="parentEventCall">클릭</button>
   </template>
   ```

### 이벤트 검증

> 이벤트의 무분별한 발신을 막기 위해 컴포넌트에 발신 가능한 이벤트 명시, 옵션스 API의 **emits**속성 사용

```javascript
export default {
  emits: ['이벤트_타입1', '이벤트_타입2', ..., '이벤트_타입N']
}
```

```html
<!-- UserProfile.vue/verification -->
<script>
  export default {
    emits: ["print-hello"],
    methods: {
      parentEventCall() {
        // emits 옵션 속성으로 print-hello 이벤트만 명시했는데
        // 다음처럼 명시되지 않은 onPrint-hello 이벤트 호출 시 경고 발생
        this.$emit("onPrint-hello");
      },
    },
  };
</script>

<template>
  <button @click="parentEventCall">클릭</button>
</template>
```

#### ❗️ emits 기능을 사용하지 않아도 $emit() 내장 메서드로 이벤트를 발신할 수 있지만 웬만하면 emits 기능을 사용해 이벤트 타입 명시 바람

### 이벤트 발신 인자와 매개변수

- `$emit()` 내장 메서드를 사용해 부모 컴포넌트로 이벤트를 발신할 때 첫 번째 인자로 부모 컴포넌트의 이벤트 타입 명시
- 두 번째 인자부터 값을 지정하면 부모 컴포넌트의 이벤트 매개변수로 값을 전달

```html
<!-- UserProfile.vue/parameter -->
<script>
  export default {
    emits: ["print-hello"],
    methods: {
      parentEventCall() {
        this.$emit("print-hello", "철수", 30);
      },
    },
  };
</script>

<template>
  <button @click="parentEventCall">클릭</button>
</template>
```

```html
<!-- App.vue/parameter -->
<script>
  import UserProfile from "./components/UserProfile.vue";

  export default {
    components: {
      UserProfile,
    },
    methods: {
      printHello(name, age) {
        alert(`안녕하세요! 저는 ${name}이고, 나이는 ${age}살입니다.`);
      },
    },
  };
</script>

<template>
  <UserProfile
    @print-hello="(name, age) => printHello(name, age)"
  ></UserProfile>
</template>
```
